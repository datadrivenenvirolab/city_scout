CityScout review

Stage 1:
PDF file type is not always enforced, some "pdf links" are actually page links
Using "after: year" in SERP search query is not reliable, often leaves out good results. Better to leave filtering for stage 2. Since CAPs cover multiple years, it's probably best to leave out the date from search query and let google suggest most relevant result. 
Stage 1 PDFlink scoring is not necessary. In my experience it is better to use results ranked by Google
There are 6 total search calls per City (3 with filetype:pdf, 3 without), because of many search terms. The results from 3 separate searches (in case with filetype:pdf) get deduped and merged. If scoring is disabled, it no longer makes sense to concatenate the results. -> I would reduce the amount of search terms so that only one search call is needed for "filetype:pdf" search

Stage 2 prompt:
Only 6000 chars are extracted (2-4 pages)
Relevance
"Must include some information about climate mitigation, energy or climate adaptation actions or targets, not only about air pollution or water." - this might not be present in first couple of pages
CorrectCity
"Only classify as "Yes" if the main subject is exactly that city." - some CAPs are shared (e.g. Helmond and Eindhoven)
"If the document focuses on private entities, No" - some action plans are done by private consultation firms (e.g. Kaunas, 2013, might be old norm, might not fit the goal)

Stage 2:
Temp PDFs not deleted automatically (maybe by design)
PDF download in fetch.py needs to be more robust, needs better anti-blocking:
Retry handling for 429, 500, 502, 503, 504 (not just ad-hoc retries)
403-specific delay window with jitter before retry (CDN cooldown)
Optional exponential backoff between retries
Per-domain minimum request spacing/rate limiting to avoid burst-triggered blocks
Per-domain persistent requests.Session reuse to keep anti-bot cookies
Last-chance retry with a fresh session + new UA after repeated 403s
More realistic referrer chain warmup (visit listing/landing page first when known)
Dynamic Accept negotiation (PDF vs HTML) based on URL characteristics
Better PDF detection by magic bytes (%PDF-), not only headers/URL
SSRF safety checks (block private/loopback/link-local targets)
Environment/config toggles for timeout/retries/backoff so behavior can be tuned per target
Atomic temp-file write (.part) should be retained, but combined with retry + validation before finalizing
Better HTML fallback parsing coverage (meta refresh / script-discovered links) plus retry of discovered link with referer context
